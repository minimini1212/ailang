# 구조 결정 — 왜 서버가 둘인가

> **정리일:** 2026-08-27 · **상태:** 기록 (이미 그렇게 만들어져 있다)
> 이 문서는 새 결정을 내리는 자리가 아니라, **이미 내려진 결정의 근거를 남기고 무엇이
> 아직 안 정해졌는지를 밝히는** 자리다. 근거를 안 적어 두면 석 달 뒤에 「왜 나눴더라」가 된다.

## §0. 이 문서를 처음 보는 사람에게

| 말 | 뜻 |
| --- | --- |
| **Spring Boot** | 자바로 웹 서버를 만드는 도구. 인증·DB 처리에 쓴다. |
| **FastAPI** | 파이썬으로 웹 서버를 만드는 도구. 가볍고, AI 라이브러리가 파이썬에 몰려 있다. |
| **LangChain** | LLM 을 부르는 코드를 정리해 주는 파이썬 라이브러리. |
| **JWT** | 「이 사람은 로그인한 아무개다」를 증명하는 서명된 문자열. |
| **컨테이너 / Docker Compose** | 프로그램을 통째로 담아 돌리는 상자 / 여러 상자를 한 번에 띄우는 도구. |

---

## §1. 선택: 자바(Spring) + 파이썬(FastAPI) 두 서버

| 근거 | 설명 |
| --- | --- |
| **AI 생태계가 파이썬에 있다** | LangChain, 임베딩, 벡터 저장소 클라이언트가 전부 파이썬이 먼저다. 자바에서 하려면 우회가 늘고, 예제와 문서가 마르다 |
| **AI 는 느리고 자주 실패한다** | 2~10초 걸리고 할당량으로 거절당한다. 인증·DB 를 다루는 서버와 **같은 스레드 풀을 쓰지 않는 편**이 안전하다 ([`ai-call-policy.md`](ai-call-policy.md) §1) |
| **AI 쪽만 따로 재시작·교체할 수 있다** | 모델을 바꾸거나 프롬프트를 고칠 때 학생의 로그인 세션이 끊기지 않는다 |
| **경계가 명확하다** | 🎯 **FastAPI 는 우리 DB 를 모른다.** 학생이 누군지도, 문제가 몇 개인지도 모른다 — 받은 문자열로 프롬프트를 만들 뿐이다 |

### 그래서 두 서버가 공유하는 것은 정확히 둘이다

```
① JWT 시크릿      Spring 이 만든 토큰을 FastAPI 가 같은 키로 검증한다 (HS256)
② HTTP 계약       docs/API_CONTRACT.md §7
```

🔴 **그 밖에는 아무것도 공유하지 않는다.** 코드도, DB 도, 라이브러리도.
공유가 늘면 나눈 이유가 사라진다.

⚠️ **①의 대가**: 시크릿이 다르면 **AI 기능만 전부 401** 이 된다. 증상이
「로그인은 되는데 개념 설명만 안 됨」으로 나타나 원인 찾기가 오래 걸린다.
→ [`../../.env.example`](../../.env.example) ②

## §2. 두 서버로 나눈 대가 — 정직하게

나눈 이상 **경계를 넘을 때마다 무언가 잃는다.** 지금 실제로 잃고 있는 것들이다.

| 잃는 것 | 어떻게 드러나나 | 어디서 다루나 |
| --- | --- | --- |
| **실패의 종류** | FastAPI 의 429 가 Spring 을 지나며 500 이 된다 | [`ai-call-policy.md`](ai-call-policy.md) R3 |
| **세션 상태** | Spring 만 로그아웃 블랙리스트를 안다. FastAPI 는 모른다 | [`../../TODOS.md`](../../TODOS.md) 2절 |
| **어휘의 단일성** | 학년 목록이 자바 enum 1곳 + 파이썬 2곳, 총 세 곳에 있다 | [`../DATA_CONTRACT.md`](../DATA_CONTRACT.md) §3 |
| **설정의 단일성** | 한 `.env` 를 두 서버가 읽는데 필요한 값이 서로 다른 키가 있다 (Redis) | [`../../.env.example`](../../.env.example) ⑤ |
| **신원** | 「서비스 호출」이라는 개념이 없어 가짜 유저 토큰을 쓴다 | [`ai-call-policy.md`](ai-call-policy.md) §4 |

🎯 **이건 「나누지 말았어야 했다」는 뜻이 아니다.** 나누면 생기는 비용이고, 그 비용을
**아는 채로** 갚아야 한다는 뜻이다. 모르면 위 다섯 개가 각각 별개의 버그로 보인다.

## §3. 이미 정해진 것들

### 왜 Oracle 인가

교육 과정에서 정해진 것으로 보인다(`gvenzl/oracle-free` 컨테이너).
⚠️ **그 대가로 네이티브 쿼리가 Oracle 전용이다** — `DBMS_RANDOM.VALUE`,
`FETCH FIRST n ROWS ONLY`. `ProblemRepository` 의 쿼리 5개가 전부 그렇다.
**DB 를 바꾸면 이 다섯 개를 다시 써야 한다.** 지금 바꿀 이유는 없지만, 알고 있을 것.

### 왜 Spring Boot 4 인가

`build.gradle` 에 `4.0.2` 로 올라가 있다. ⚠️ 최신 버전이라 대가가 이미 두 번 나왔고,
**둘 다 주석으로 근거가 남아 있다** — 좋은 습관이다.

- `spring-dotenv` 4.0.0 이 안 붙어 `springboot4-dotenv` 로 교체
- `starter-web` 이 `jackson-databind` 를 전이 포함하지 않아 명시적으로 추가

🎯 **버전 때문에 우회한 자리는 반드시 주석으로 근거를 남긴다.** 안 남기면 다음 사람이
「왜 이것만 명시했지」 하고 지운다.

### 왜 Docker Compose 에 Spring 이 없나

Oracle · Redis · FastAPI 셋만 컨테이너로 뜨고, **Spring 은 IDE 에서 로컬 실행**한다.
개발 중에는 이게 편하다(재시작이 빠르고 디버거가 붙는다).

🔴 **그 대가로 주소가 안쪽과 바깥쪽이 다르다.**

```
Redis    Spring(호스트)에서는  localhost:6380
         FastAPI(컨테이너)에서는 ailang-redis:6379   ← 같은 Redis 다
```

배포 대상이 정해지면 이 구성이 통째로 바뀐다 — 아직 안 정했다 (§4).

## §5. 폴더 구조

Spring 쪽은 **도메인별 분리**를 쓴다 — `domain/<업무>/{controller,service,repository,entity,dto,enums,exception}`.

🎯 계층별 분리(`controllers/`, `services/`, …)와의 차이는 **「무엇을 고칠 때 몇 폴더를
여는가」**다. 「문제 제출 로직을 고친다」가 폴더 하나 안에서 끝나는 쪽을 골랐다.

⚠️ **대신 도메인 간 호출 규칙이 필요하다.** 지금 `ProblemServiceImpl` 은
`ChapterRepository` 와 `UserRepository` 를 직접 들고 있다 — 남의 도메인의 레포지토리다.
**레포지토리가 아니라 서비스를 통해 부르는 편**이 맞지만, 지금 규모에서 급한 문제는 아니다.
