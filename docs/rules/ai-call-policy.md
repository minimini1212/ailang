## §0. 이 문서를 처음 보는 사람에게

| 말 | 뜻 |
| --- | --- |
| **LLM / Gemini** | 문장을 만들어 주는 외부 AI 서비스. 우리 서버 밖에 있고, 느리고, 가끔 실패한다. |
| **프롬프트** | 그 AI 에게 보내는 지시문. 학년·단원·문제 본문을 끼워 넣어 만든다. |
| **할당량(quota)** | 무료 등급에서 하루/분당 부를 수 있는 횟수 한도. 넘으면 거절당한다. |
| **타임아웃** | 「이만큼 기다렸는데 답이 없으면 포기한다」는 제한 시간. |
| **트랜잭션** | DB 작업 여러 개를 한 덩어리로 묶는 것. 묶여 있는 동안 DB 연결을 붙잡는다. |

## §1. 외부 모델 호출은 왜 다르게 다뤄야 하나

우리 DB 조회는 밀리초 단위로 끝나고 거의 실패하지 않는다. **Gemini 호출은 둘 다 아니다.**

```
DB 조회       5ms      거의 항상 성공
Gemini 호출   2~10초   할당량·모델 거부·형식 오류·네트워크로 실패
```

🎯 **1000배 느리고 자주 실패하는 것을, 빠르고 안 실패하는 것과 같은 방식으로 다루면
느림과 실패가 시스템 전체로 번진다.** 이 문서는 그 번짐을 막는 규율이다.

## §2. 규율

### R1 🔴 트랜잭션 안에서 부르지 않는다

```
❌  @Transactional {  ← 여기서 Oracle 커넥션을 잡고
      HTTP 호출 (5초)  ← 5초 내내 붙잡고 있다
      저장
    }

✅  HTTP 호출 (5초)      ← 커넥션 없이
    @Transactional {     ← 저장할 때만 잡는다
      저장
    }
```

**왜**: 커넥션 풀은 유한하다. 동시에 열 명이 AI 문제를 요청하면 커넥션 열 개가 5초씩
묶이고, 그동안 **로그인·문제 조회 같은 관계없는 요청까지 대기한다.**

🔴 지금 `ProblemServiceImpl.getAiProblem` 이 이 상태다.

### R2 🔴 모든 외부 호출에 연결·읽기 타임아웃을 건다

`RestTemplate` 의 기본 타임아웃은 **무한**이다. AI 서버가 죽으면(연결 거부) 즉시
실패하지만, **살아서 응답만 안 주면** 톰캣 스레드가 영원히 묶인다. 스레드가 다 묶이면
서버가 요청을 못 받는다 — 죽지 않은 채로 멈춘다.

- 연결 타임아웃: 짧게 (수 초)
- 읽기 타임아웃: **모델의 실제 응답 시간보다 넉넉하되 무한이 아니게**
- ⚠️ 값은 코드가 아니라 설정에 둔다.

🔴 지금 `AppConfig.restTemplate` 은 `new RestTemplate()` 그대로다.

### R3 🔴 실패의 종류를 경계 너머까지 보존한다

FastAPI 는 이미 잘하고 있다 — 할당량 초과를 `GeminiQuotaException` 으로 잡아 **429** 로
내린다. 그런데 Spring 을 거치면서 **그 정보가 사라진다.**

```
Gemini 할당량 초과
   → FastAPI: 429 "요청 한도를 초과했습니다"      ✅ 정확하다
   → RestTemplate: HttpClientErrorException 던짐
   → GlobalExceptionHandler 의 RuntimeException 분기
   → 학생: 500 "서버 내부 에러"                    🔴 정보가 없다
```

**최소한 이 넷은 구분되어야 한다.**

| 무슨 일 | 학생에게 | 우리가 할 일 |
| --- | --- | --- |
| 할당량 초과 | 「지금은 붐빕니다. 잠시 후 다시」 | 사용량을 본다 |
| 모델이 형식을 어김 | 「다시 시도해 주세요」 | 프롬프트를 고친다 |
| AI 서버 응답 없음 | 「일시적으로 이용할 수 없습니다」 | 서버를 본다 |
| 우리 코드 오류 | 「서버 오류」 | 고친다 |

🎯 **네 가지가 한 메시지면, 학생은 재시도할지 기다릴지 판단할 수 없고 우리는 원인을 모른다.**

### R4 🔴 학생 개인정보를 프롬프트에 넣지 않는다

**지금 프롬프트에 들어가는 것** (concept · problem 두 서비스 모두):

```
학년 (ELEM_3 등)  ·  단원명  ·  문제 본문  ·  난이도
```

✅ **이 상태가 맞다. 유지한다.**

🔴 **넣지 않는다**: 이메일, 닉네임, 유저 id, 정답 이력, 실명, 학교, 그 밖에 개인을
가리키는 무엇이든. 학생은 미성년자다.

⚠️ **챗봇은 예외적으로 학생이 쓴 문장이 그대로 나간다.** 학생이 대화에 개인정보를 쓰면
그것이 외부로 간다. 이 위험을 줄이는 방법(안내 문구·마스킹)은 아직 안 정했다.

### R5 모델의 응답은 **믿을 수 없는 입력**이다

생성된 문제를 DB 에 저장하기 전에 확인한다.

| 확인 | 왜 |
| --- | --- |
| `options` 길이 ≤ 1000 | 🔴 `PROBLEMS.OPTIONS` 가 `VARCHAR2(1000)`. LaTeX 섞인 보기 4개는 넘길 수 있다 |
| `problem_type` 이 어휘에 있나 | `ProblemType.valueOf` 가 던진다 |
| `answer` 가 보기 번호 범위인가 | 프롬프트가 「1~4 중 하나」를 요구하지만 지킨다는 보장은 없다 |
| JSON 으로 파싱되나 | 지금은 실패하면 그냥 던진다 |

⚠️ **JSON 파싱은 지금 취약하다** (`problem_service.py`). 응답에 ` ``` ` 이 있으면
`parts[1]` 을 쓰는데, 코드블록이 두 개면 엉뚱한 걸 집고, 없으면 전체를 파싱한다.
모델이 설명 문장을 앞에 붙이면 그대로 실패한다.

🎯 **재시도를 넣더라도 횟수를 정해서 넣는다.** 무한 재시도는 할당량만 태운다.

## §3. 호출 자리는 한 곳뿐이다

```
Spring 에서 FastAPI 를 부르는 유일한 자리:  global/client/AiServerClient
FastAPI 에서 Gemini 를 부르는 자리:        app/services/*_service.py
```

🔴 **다른 곳에서 직접 `RestTemplate` 이나 `ChatGoogleGenerativeAI` 를 만들지 않는다.**
타임아웃·인증·실패 처리를 한 곳에서만 강제할 수 있어야 하기 때문이다.
호출하는 쪽마다 지키게 하면 언젠가 한 곳이 안 지킨다.

**프롬프트도 마찬가지다.** 서비스 파일 안에 한 덩어리로 두고, 라우터나 다른 모듈로
흩뜨리지 않는다.

## §4. 내부 호출의 신원 — ⚠️ 지금 방식은 임시다

`AiServerClient.withAuth` 는 호출할 때마다
`jwtTokenProvider.createAccessToken("service@internal")` 로 **학생 토큰과 똑같은 모양의
토큰**을 만든다.

| | 지금 | 문제 |
| --- | --- | --- |
| 서명 키 | 학생 토큰과 같음 | 서비스 토큰이 유출되면 학생 토큰으로도 쓰인다 |
| subject | `service@internal` (없는 유저) | Spring 본체로 들여보내면 `UserNotFound` 로 막히긴 한다 |
| 구분 claim | 없음 | FastAPI 는 「이게 서비스인지 학생인지」 알 수 없다 |
| 만료 | 1시간 | 매 호출마다 새로 만든다 — 낭비지만 위험은 아니다 |

🎯 **왜 이렇게 됐나**: FastAPI 호출에 JWT 가 빠져 401 이 나던 것을 고치면서, 가장 가까이
있던 토큰 발급기를 쓴 것이다. 기능은 붙었지만 **「서비스 신원」이라는 개념은 안 생겼다.**

정할 것: 별도 claim(`type: service`)을 넣고 FastAPI 가 그것을 요구할지, 아니면 공유 시크릿
헤더 같은 다른 방식을 쓸지. → [`../../TODOS.md`](../../TODOS.md) 2절

## §5. 지금 어긋나 있는 자리 — 실측

| # | 어디 | 어긴 규율 |
| --- | --- | --- |
| 1 | `ProblemServiceImpl.getAiProblem` | R1 — `@Transactional` 안에서 HTTP 호출 |
| 2 | `AppConfig.restTemplate` | R2 — 타임아웃 없음 |
| 3 | `GlobalExceptionHandler` | R3 — 429·401·422 를 전부 500 으로 |
| 4 | `problem_service.py` | R5 — 길이 검증 없음, JSON 파싱 취약 |
| 5 | `concept_service.py` · `problem_service.py` | ✅ R4(개인정보)는 지키고 있다 — 코드로 확인 |
| 6 | 세 서비스 전부 | 🔴 **429 처리가 실제로 도는지 확인된 적이 없다** — 아래 |
| 7 | `problem_service.py:42` | 🔴 모르는 난이도를 **조용히 「중간」으로 바꿔치기**한다 — 아래 |

### 🔄 2026-08-27 정정 — 「FastAPI 는 429 를 잘 내린다」는 근거가 없었다

이 문서는 원래 R3 절에서 *"FastAPI 는 이미 잘하고 있다"* 고 단정했다.
**그 ✅ 는 코드 모양만 보고 붙인 것이고, 아무도 실제 429 를 본 적이 없다.**

```python
except ResourceExhausted:        # ← langchain 이 예외를 감싸면 여기 안 걸린다
    raise GeminiQuotaException()
```

⚠️ `langchain_google_genai` 가 하위 예외를 자기 예외로 감싸면 이 `except` 가 안 잡히고
**429 대신 500** 이 나간다. 그러면 Spring 쪽 429 전달(R3)을 고쳐도 소용이 없다.
그리고 `PermissionDenied`(키 오류) · `InvalidArgument`(프롬프트 초과) ·
`DeadlineExceeded` · `ServiceUnavailable` 은 **전부 500 한 덩어리**가 된다 —
🔴 **Spring 에 닿기 전에 이미 합쳐지므로, Spring 만 고쳐서는 구분이 복원되지 않는다.**

🎯 **할 일은 재현 하나다.** 할당량을 일부러 넘겨 보고, 결과가 어느 쪽이든
이 절을 근거와 함께 갱신한다. `timeout`·`max_retries` 미지정도 같이 정한다.

### 🔴 어휘 밖의 값을 기본값으로 접지 않는다

`problem_service.py:41~42` — 붙어 있는 두 줄의 실패 방식이 **정반대**다.

```python
grade_name      = GRADE_DISPLAY.get(grade, grade)             # 원본을 통과시킨다
difficulty_name = DIFFICULTY_DISPLAY.get(difficulty, "중간")   # 🔴 다른 값으로 바꾼다
```

**42행이 더 나쁘다.** 41행은 이상한 값이 프롬프트에 그대로 들어가 눈에 띄지만,
42행은 **정상으로 보이는 다른 난이도**가 된다. 그리고 Spring 은 그 결과를
**요청했던 난이도로** 저장한다(`ProblemServiceImpl.java:224`) — DB 의 `DIFFICULTY` 와
실제 문제 수준이 어긋나고, **어긋난 사실이 아무 데도 안 남는다.**

📌 어휘 밖의 값은 **거절**한다. 기본값으로 접는 것은 「모른다」를 값으로 접는 것이다.

⚠️ **`GRADE_DISPLAY` 딕셔너리가 두 파일에 복사돼 있다.** 학년이 늘면 자바 enum 까지
세 곳을 고쳐야 하고, `GRADE_DISPLAY.get(grade, grade)` 라 빠져도 예외 없이
`"HIGH_2"` 가 그대로 프롬프트에 들어간다 — **조용히 이상한 설명이 나간다.**

## §6. 아직 안 정한 것 — 🔴 혼자 정하지 말 것

| 항목 | 왜 지금 못 정하나 |
| --- | --- |
| 모델 교체 (`gemini-2.5-flash` → ?) | 비용·품질·속도의 문제라 사용자가 정한다. 🎯 바꿀 때 이 문서에 근거를 남긴다 |
| 재시도 횟수와 대기 | 실제 실패율을 재고 나서 |
| 응답 캐싱 | 같은 문제의 개념 설명은 매번 새로 만들 필요가 없다. ⚠️ 다만 학년별로 달라야 한다 |
| 챗봇의 개인정보 안내 | R4 의 ⚠️ |
| RAG 검색 결과가 없을 때의 동작 | 빈 컨텍스트로 그냥 답할지, 「자료 없음」을 밝힐지. 🔴 근거 없는 답을 근거 있는 답처럼 보이게 하면 안 된다 |
