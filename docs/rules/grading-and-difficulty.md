# 채점·난이도·통계 규율 — 누가 정답을 정하는가

> **작성일:** 2026-08-27 · **상태:** 🔴 **현재 코드는 이 규율을 지키지 않는다.**
> 이 문서는 「지켜지고 있는 것」의 기록이 아니라 **「무엇이 지켜져야 하는가」의 기준**이다.
> 어긋난 자리는 아래에 전부 적어 두었고, 고칠 목록은 [`../../TODOS.md`](../../TODOS.md) 1절에 있다.

## §0. 이 문서를 처음 보는 사람에게

| 말 | 뜻 |
| --- | --- |
| **채점** | 학생이 낸 답이 맞았는지 정하는 일. |
| **자가채점** | 학생 본인이 「맞았다/틀렸다」를 스스로 표시하는 방식. 단답형에 쓰고 있다. |
| **정답률** | 그 학생이 그 챕터에서 맞힌 수 ÷ 푼 수. |
| **난이도 조정** | 그 정답률에 따라 다음 문제를 더 쉽게/어렵게 바꾸는 것. |
| **풀이 이력 / 챕터 통계** | 푼 한 건 한 건의 기록 / 그것을 합쳐 놓은 요약값. |

---

## §1. 이 규율이 왜 필요한가

이 제품이 파는 것은 문제가 아니라 **「너에게 맞는 문제」** 다. 그 「맞는」을 정하는 것은
정답률 하나뿐이다.

```
정답률  →  난이도  →  다음에 나올 문제  →  학생이 푼다  →  정답률
   ▲                                                        │
   └────────────────────────────────────────────────────────┘
```

🔴 **이 고리 안에 클라이언트가 들어와 있으면 고리 전체가 의미를 잃는다.**
정답률이 조작 가능하면 난이도가 조작 가능하고, 난이도가 조작 가능하면 「맞춤형」이
남아 있지 않다. 다른 결함은 기능을 고장 내지만, 이 결함은 **제품을 고장 낸다.**

---

## §2. 규율

### R1 🔴 채점은 서버 안에서만 일어난다

> 클라이언트가 보낸 **정답 판정 결과**를 저장하지 않는다.

클라이언트가 보내도 되는 것은 **학생이 무엇을 입력했는가**(`userAnswer`)까지다.
그것이 맞았는지는 서버가 정한다.

### R2 🔴 정답은 채점 시점 전에 응답에 실리지 않는다

`answer` 와 `explanation` 을 돌려주는 자리는 **제출 이후**뿐이다.
정답을 돌려주는 엔드포인트는 코드에서 **세 가지를 명시적으로 확인**한다.

1. 어떤 `ProblemType` 을 위한 것인가
2. 이 학생이 이 문제를 이미 제출했는가
3. 왜 이 시점에 필요한가 (주석으로)

### R3 🔴 두 개의 id 가 오면 서버가 관계를 증명한 뒤에 쓴다

요청이 `problemId` 와 `chapterId` 를 같이 들고 오면, **그 문제가 그 챕터에 속하는지**를
확인한 다음에 통계를 건드린다. 확인 없이 쓰면 학생이 통계의 대상 챕터를 직접 고르는 셈이다.

### R4 🔴 「모른다」를 「틀렸다」로 접지 않는다

| 상황 | ❌ 하면 안 되는 것 | ✅ 해야 하는 것 |
| --- | --- | --- |
| 판정값이 요청에 없다 | 오답으로 기록 | **400 으로 거부** |
| 3문제 미만 풀었다 | 낮은 실력으로 취급 | 난이도 유지 (지금 맞게 하고 있다) |
| 학년이 null 이다 | 기본 학년으로 대체 | 「미입력」 상태로 다루고 학년을 받는다 |
| AI 호출이 실패했다 | 빈 문자열 저장 | 실패를 실패로 남긴다 |

🎯 **「맞음/틀림」에는 언제나 「아직 안 함」이 따라온다.** 두 값짜리 자리에 세 번째 상태가
필요해지면 boolean 을 늘리지 말고 상태를 만든다.

### R5 난이도 규칙은 한 곳에만 산다

현재 `UserChapterStats.recordAnswer` / `recalculateDifficulty` 와 `Difficulty.upgrade()`
`downgrade()` 안에만 있다. **좋은 상태다 — 흩뜨리지 말 것.**
컨트롤러나 서비스에서 정답률을 다시 계산해 분기하지 않는다.

### R6 이력은 사실, 통계는 요약. 어긋나면 이력이 맞다

`USER_PROBLEM_HISTORY` 는 되돌아볼 수 있는 사실이고, `USER_CHAPTER_STATS` 는 그 요약이다.
- 이력은 지우지 않는다.
- `USER_ANSWER` 는 **정규화하지 않은 원문**을 넣는다. 채점 규칙이 바뀌었을 때
  「그때 학생이 정확히 뭐라고 썼나」를 되짚을 수 있어야 한다.

⚠️ **지금은 통계를 이력으로부터 다시 만들 수 없다.** 난이도가 「그때의 값에서 한 칸」씩
움직이는 경로 의존적 값이라, 같은 이력을 재생해도 같은 난이도가 안 나온다. 잘못 채점된
건을 정정하는 기능이 필요해지면 **재계산 경로를 먼저** 만들어야 한다.

### R10 🔴 통계를 고쳐 쓸 때는 잠금을 «먼저» 잡는다

정답률은 「읽고 고쳐 쓰는」 값이다. 같은 학생이 두 번 동시에 제출하면 — 화면에서 버튼이
두 번 눌리는 것으로 충분하다 — 잠금이 없을 때 셋이 깨진다.

| 무엇이 겹치나 | 결과 |
| --- | --- |
| 통계 행이 없을 때 둘 다 만든다 | 유일 제약 위반 → **학생이 답을 냈는데 500** |
| 둘 다 같은 값을 읽고 각각 +1 | **한 건이 사라진다.** 사라지는 것은 정답률이고, 정답률이 난이도를 정한다 |
| 같은 문제인데 둘 다 「첫 제출」로 읽는다 | 한 문제가 정답률에 **두 번** 들어간다 |

🎯 **순서가 규칙이다.** 잠금을 먼저 잡고 그 다음에 이력을 조회하면 셋이 함께 닫힌다 —
뒤 요청은 앞 요청이 커밋한 뒤에 이력을 읽으므로 세 번째도 자연히 없어진다.

- 읽기만 할 때와 고쳐 쓸 때의 **조회 메서드가 다르다** — `docs/DATA_CONTRACT.md`
  「USER_CHAPTER_STATS」 절에 어느 것을 쓸지 적혀 있다.
- 행을 «만드는» 일은 **별도 트랜잭션**이어야 한다. 같은 트랜잭션에서 제약 위반을 잡으면
  그 트랜잭션은 롤백밖에 못 한다.
- 🔴 **그리고 «잡는 자리» 도 그 트랜잭션 밖이어야 한다** — 아래 R10-1 참고.
- ⚠️ **이 잠금을 잡은 트랜잭션에서 외부 호출을 하지 않는다.** 잠금은 커밋까지 유지된다.

### R10-1 🔴 실패를 삼키는 자리는 그 실패가 일어난 트랜잭션 «밖» 이다

> 🔄 **2026-09-15 신설.** R10 을 지켰다고 믿은 코드가 **나흘 동안 여전히 500 을 내고
> 있었다.** 실제 DB 로 동시 제출을 재 보고 나서야 드러났다.

「행을 만드는 일은 별도 트랜잭션」까지는 맞게 했는데, 제약 위반을 **그 별도 트랜잭션
메서드 안에서** 잡았다. 그러면 이렇게 된다:

```
saveAndFlush 실패  → 이 트랜잭션이 「롤백 전용」으로 표시된다
catch 로 삼킨다    → 예외는 사라진다. 여기까지는 의도대로다
메서드가 정상 반환  → 스프링이 커밋을 시도한다
                  → 롤백 전용이므로 UnexpectedRollbackException
                  → 부르는 쪽으로 터져 나간다. 학생은 여전히 500 을 본다
```

**예외의 이름만 바뀌고 증상은 그대로였다.** `DataIntegrityViolationException` 이
`UnexpectedRollbackException` 이 됐을 뿐이다.

🎯 **규칙:** 실패를 「없던 일」로 만들려면, 그 실패로 더럽혀진 트랜잭션이 **이미 끝난
뒤에** 잡아야 한다. 안쪽은 그냥 던지고, 바깥이 잡는다.

```
안쪽 (REQUIRES_NEW)  : 만들기만 한다. 제약 위반은 «그대로 던진다» → 깨끗이 롤백
바깥 (원래 트랜잭션)  : try { 만들기 } catch (제약위반) { 남이 먼저 만든 것 } → 다시 조회
```

⚠️ **이 규칙은 「일단 넣어 보고 실패하면 남이 먼저 한 것」 패턴 전부에 해당한다.**
지금은 통계 행 하나뿐이지만, 같은 모양이 또 나오면 같은 함정이 기다린다.

🔬 **검사가 있다.** `SubmitAnswerConcurrencyTest` — 실제 DB 가 필요하고, DB 가 없으면
조용히 통과하지 않고 건너뛴다.

### R7 검증되지 않은 정답으로 난이도를 정하지 않는다

`SOURCE_TYPE = 'AI'` 인 문제는 정답이 사람에게 검증되지 않았다.
- 맞춤 문제·랜덤 문제·진단 테스트는 **`REAL` 만** 뽑는다 (현재 쿼리 5개 모두 그렇다).
- 새 조회 쿼리를 쓸 때 이 조건을 빠뜨리지 않는다.
- ⚠️ AI 문제의 제출 결과가 통계에 들어가야 하는지는 **아직 안 정했다** — 지금은 들어간다.
  [`../../TODOS.md`](../../TODOS.md) 8절.

### R9 🔴 문제가 없으면 «없다» 고 하지 말고 이웃 난이도를 준다

챕터에 그 난이도의 문제가 **0건일 수 있다.** 실측(2026-09-09)에서 (챕터 8 × 난이도 3)
24칸 중 **7칸이 비어 있었다** — 난이도가 단원별로 몰려 있어서다.

```
입체도형        하   0 · 중   0 · 상 168
정수와 유리수    하 167 · 중   0 · 상   0
```

통계가 없는 학생의 초기 난이도는 중(MEDIUM) 이다. 그래서 학생이 「입체도형」을
**처음 열면** 중 0건이라 문제를 못 받고 **404** 가 났다.

- **요청 난이도 → 한 단계 아래 → 나머지** 순으로 찾는다 (`DifficultyFallback`).
  쉬운 쪽을 먼저 보는 이유는, 못 풀면 학생이 그만두기 때문이다.
- 🔴 **난이도를 «바꿔치기» 하지 않는다.** 응답에는 실제로 준 문제의 난이도가 그대로
  실려 나간다 — 화면이 학생에게 사실대로 보여 줄 수 있어야 한다 (R4 와 같은 원칙).
- 세 난이도 모두 0건이면 그때는 정말로 없는 것이다. 404 가 맞다.

⚠️ 이건 **고장을 막은 것이지 고친 것이 아니다.** 근본은 난이도 축을 무엇으로 정하느냐다
([`../research/chapter-granularity-2026-09-09.md`](../research/chapter-granularity-2026-09-09.md) §4).

### R8 채점 로직은 순수 함수로, 검사와 함께

`AnswerNormalizer` · 난이도 전이 · 정답률 계산은 DB 도 네트워크도 필요 없다.
**검사를 못 붙일 이유가 없는 코드다.** 새 규칙을 넣을 때 검사를 같이 넣는다.

🔴 **새 검사는 옛 코드에서 빨간불이어야 한다.** 양쪽 다 통과하면 아무것도 못 박은 게 없다.

### ✅ 정규화를 고친 방식 — 「못 맞히는 쪽」을 골랐다

예전에는 아는 명령어를 바꾼 뒤 **남은 `\word` 를 전부 지웠다.** 그래서 서로 다른 답이
같은 문자열이 됐다 (`$\sqrt{2}$` → `2`, `$\pi$` → 빈 문자열).

고칠 방향이 둘이었다.

| | |
| --- | --- |
| ① 모르는 표기도 «뜻» 을 알아내 비교한다 | 수식 파서가 필요하다. 이 과제의 크기가 아니다 |
| ② **모르는 표기는 그대로 두고 글자로 비교한다** | ✅ 골랐다 |

②는 `√2` 라고 쓴 학생을 못 맞힐 수 있다. 그래도 이쪽이 맞다 —
🎯 **틀린 답을 정답으로 만드는 것보다, 맞는 답을 못 알아보는 편이 낫다.**
전자는 정답률을 오염시켜 난이도 고리 전체를 망가뜨리고, 후자는 그 한 문제로 끝난다.

📌 정규화 결과가 **비면 아예 비교하지 않는다.** 실제 정답 중 `"$"` 와 `"$\bigcirc$"` 가
그런 경우인데, 그대로 두면 학생이 `"$"` 한 글자만 내도 정답이 된다.

## §4. 아직 안 정한 것 — 🔴 혼자 정하지 말 것

### 단답형을 어떻게 채점할 것인가

지금의 자가채점은 **의도된 설계**로 보인다 — 수학 단답형은 `2/4` 와 `1/2`, `0.5` 가 다
맞는 답이라 문자열 비교가 어렵기 때문이다. 그래서 「학생이 직접 본다」로 우회했다.

⚠️ **그런데 그 우회가 정답률까지 학생에게 넘겼다.** 선택지는 대략 셋이다.

| 안 | 어떻게 | 대가 |
| --- | --- | --- |
| ① 서버 채점 + 이의제기 | `AnswerNormalizer` 로 채점하고, 학생이 「이것도 맞다」를 신고 | 정규화가 부족한 만큼 오판이 난다. 신고 처리 화면이 필요하다 |
| ② 자가채점 유지 + 통계 분리 | 판정은 학생이, **난이도에는 객관식만** 반영 | 단답형이 많은 챕터는 난이도가 안 움직인다 |
| ③ 자가채점 유지 + 그대로 | 지금 상태 | 정답률이 근거가 되지 못한다 |

🔴 **이건 학습 경험의 문제라 사용자가 정한다.** 정해지면 이 절을 결정 기록으로 바꾸고,
[`../../TODOS.md`](../../TODOS.md) 1절과 [`../API_CONTRACT.md`](../API_CONTRACT.md) §5 를 같이 고친다.

  누적 정답률이라 잘 안 움직인다. ⚠️ 최근 N문제 기준으로 바꿀지는 실측 후에 볼 일이다.
- **진단 테스트 20문제 결과를 초기 난이도에 반영할 것인가** — 지금은 반영되지 않는다.
  진단을 보고도 모든 챕터가 `MEDIUM` 에서 시작한다.
