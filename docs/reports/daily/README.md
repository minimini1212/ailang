# docs/reports/daily — 일일 진행 리포트

**성격:** 개발·조사 진행 기록. 「그날 무엇을·왜·어떤 파일·어디까지」를 남긴다.

- 파일명: `REPORT_<YYYY-MM-DD>.md` (예: `REPORT_2026-08-27.md`).
- 형식: 한 줄 요약 → 지금 어디에 있나 → 작업별 상세 → 검증 → 한눈에 보기.
- 같은 날 추가 작업은 **새 파일을 만들지 말고 그날 파일에 이어 붙인다.**
- 초안은 그날의 git 커밋·변경 파일에서 뽑고, 사람이 다듬는다.
- 멘토 보고용 정리본은 여기 두지 말고 [`../mentor/`](../mentor/) 로.

## 🔴 「검증」 절에 무엇을 적나

🔄 **2026-09-15 정정.** 이 줄은 오랫동안 「테스트가 1개뿐이다」라고 적혀 있었다.
**검사 건수는 여기 적지 않는다** — 숫자는 반드시 낡는다. 진실은
[`../../../TODOS.md`](../../../TODOS.md) 5절에 있다.

요점은 건수가 아니라 이것이다: 「돌려 봤다」와 「검사가 통과했다」와 「눈으로 봤다」는
전부 다른 신뢰도인데, 안 구분하면 리포트가 실제보다 단단해 보인다.
🔴 그리고 **「검사가 있다」와 「검사를 실제로 돌렸다」도 다르다** — 2026-09-11 에 58건을
붙여 놓고 한 번도 안 돌린 채 나흘을 보냈고, 돌려 보니 그동안 「고쳤다」고 적어 둔 것이
안 고쳐져 있었다.

| 이렇게 적는다 | 이렇게 적지 않는다 |
| --- | --- |
| 「검사 N건 통과 (새로 붙인 M건 포함)」 | 「테스트 통과」 |
| 「기동 로그에서 적재 N건 확인」 | 「적재 정상」 |
| 🔴 「컴파일 못 해 봄 — 이유」 | (아무 말 안 함) |

🎯 **못 한 것을 적는 것이 리포트의 값이다.** 안 적으면 다음 사람이 「확인됐다」로 읽는다.

## 🔴 새 검사를 붙였다면 옛 코드에서 빨간불을 확인한다

「검사 M건 추가」라고 쓰기 전에, **고치기 전 상태로 되돌려 실제로 실패하는지** 본다.
양쪽 다 통과하는 검사는 아무것도 못 박은 게 없다. 확인했으면 리포트에 그렇게 적는다.
