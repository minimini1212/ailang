### 🎯 노트가 찾은 결함 두 개가 실제로 닫혔다

이게 이번 갱신에서 가장 적을 만한 대목이다.

```
노트를 쓰면서 코드를 한 줄씩 읽었다
  → 「이건 문제다」라고 적어 둔 것이 둘 있었다
       ① 객관식 정답 확인이 «부분 문자열» 검사다 ("12" 가 통과한다)
       ② 로그아웃 키가 두 파일에 각각 있는데 어긋남을 확인하는 검사가 없다
  → 같은 날 밤에 둘 다 코드와 검사가 들어갔다
  → 노트에 「고치는 방법」으로 적어 둔 코드와 «같은 모양» 으로 고쳐졌다
```

🔴 **①은 순서가 반대였다는 점이 중요하다.** 「고치고 나서 검사를 붙였다」가 아니라
**「검사를 붙였더니 5건이 빨간불이 되어 결함이 드러났다」**이다. 앞엣것은 내가 아는
결함을 내가 다시 확인한 것이고, 뒤엣것은 **내가 모르던 것을 검사가 알려 준 것**이다.

## §3 🔴 노트를 훑다가 찾은 것 — 학년 어휘가 다섯 곳에 있다

§2 에서 「검색어에 안 걸리는 낡음이 남아 있을 수 있다」고 적었으므로, 그것을 닫으려고
**노트가 인용한 코드 이름을 전부 뽑아 실제 코드와 대조**했다.

```
노트 27개에서 백틱으로 감싼 이름을 뽑는다
  → 두 저장소의 소스 전체(61만 자)에서 그 이름을 찾는다
  → 없는 것만 추린다
```

결과: **대부분 오탐이었다.** 「`Difficulty.MEDUIM` 으로 오타 내면」처럼 **일부러 없는
이름을 적은 곳**이 걸렸다. 진짜 낡은 것은 **하나** — 필터 노트의 맨 끝 정리표에
「역할 규칙이 하나도 없다」가 남아 있었다. 본문은 고쳤는데 **표를 놓쳤다.**

🎯 **여기서 배울 것: 같은 문서 안에서도 「본문」과 「요약표」는 따로 낡는다.**

### 그 과정에서 «코드» 쪽 사실을 하나 더 쟀다

노트가 「학년 목록이 자바 1곳 + 파이썬 2곳, **총 세 곳**에 복사돼 있다」고 적어 뒀길래
지금도 그런지 셌다. **다섯 곳이었다.**

| 어디 | 무엇 | 빠뜨리면 |
| --- | --- | --- |
| `Grade` enum (자바) | 정본 | — |
| `concept_service.py` | `GRADE_DISPLAY` | 🔴 **조용히 넘어간다** |
| `problem_service.py` | `GRADE_DISPLAY` | 🔴 **조용히 넘어간다** |
| (화면) `api.types.ts` | `Grade` 유니온 타입 | 컴파일이 막는다 |
| (화면) `grades.ts` | 목록 + 이름표 2벌 | 컴파일이 막는다 |

**어떻게 셌나** — 여덟 값(`ELEM_3` ~ `HIGH_1`)이 **전부** 나오는 파일만 「정의한 곳」으로
셌다. 한두 개만 언급한 파일(6개)은 뺐다.

🔴 **파이썬 두 곳이 위험하다.** 학년을 못 찾으면 `GRADE_DISPLAY.get(grade, grade)` 가
학년 **코드**를 그대로 돌려준다. 그러면 모델은 「`MIDDLE_4` 학년 수준으로 설명해 달라」를
받게 되고 **아무 데서도 에러가 안 난다.** 화면 두 곳은 타입이 잡아 주므로 안전하다.

⚠️ **고치는 방향은 정해야 한다** — FastAPI 가 학년명을 Spring 에게서 받을지, 어휘 파일을
공유할지. 서버를 나눈 대가라 공짜 해법이 없어서 `TODOS.md` 4절에 올렸다.
