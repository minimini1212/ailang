## §4 🔴 같은 파일 두 줄 차이로 정책이 반대였다

§3 에서 「학년 어휘가 다섯 곳에 있다」를 재면서, 그중 두 곳을 열어 보다가 찾았다.

```python
grade_name = GRADE_DISPLAY.get(grade, grade)          # ← 모르면 «그대로 넘긴다»
# 🔴 어휘 밖의 값을 기본값으로 접지 않는다. 조용히 「중간」으로 바꿔치기하면 ...
if difficulty not in DIFFICULTY_DISPLAY:               # ← 모르면 «거부한다»
    raise LlmBadResponseException(...)
```

🎯 **주석이 바로 위 줄이 하는 일을 금지하고 있었다.** 난이도는 모르는 값을 거부하는데,
두 줄 위의 학년은 조용히 접고 있었다.

**무엇이 문제였나 (역할 → 작용 → 결과)**

```
학년 이름을 못 찾으면 → 학년 «코드» 를 그대로 돌려준다
  → 프롬프트에 「학생 학년: MIDDLE_4」 가 실린다
  → 모델은 그 말을 «알아들은 척» 답한다
  → 🔴 에러가 어디서도 안 난다. 학생은 자기 수준과 안 맞는 설명을 받는다
```

### 무엇을 했나

**결정이 필요한 부분은 건드리지 않았다.** 「FastAPI 가 학년명을 Spring 에게서 받을지」는
서버를 나눈 대가 자체라 열어 뒀다. 대신 **이미 정해져 있는 규칙**(「모르는 값을 접지
않는다」)을 **일관되게** 적용했다 — 바로 아래 난이도 줄이 그 규칙의 본보기였다.

| | 전 | 후 |
| --- | --- | --- |
| 학년 어휘가 몇 곳에 | **다섯** | **셋** (파이썬 두 벌을 한 곳으로) |
| 모르는 학년이 오면 | 🔴 조용히 코드를 프롬프트에 넣는다 | **거부한다** |
| 모르는 난이도가 오면 | 거부한다 | 거부한다 (그대로) |

새 파일 `ai-server/app/vocabulary.py` 하나가 생겼고, 두 서비스가 그것을 쓴다.
⚠️ 그 파일 맨 위에 **「여기 있는 값은 정본이 아니다」**라고 적어 뒀다 — 정본은 여전히
Spring 의 enum 이다.

## §5 🔴 살려 온 실패의 종류를 «마지막 한 칸» 에서 뭉개고 있었다

§4 를 하고 나서 화면 쪽에 남아 있던 에러 처리 네 곳을 마저 옮기다가 찾았다.

개념 설명 화면은 실패를 이렇게 다루고 있었다.

```
400 이면   → 화면이 «자기 문구» 를 쓴다
429 이면   → 화면이 «자기 문구» 를 쓴다
그 밖에는  → 전부 「개념 설명을 받지 못했습니다」
```

**그래서 이렇게 됐다.**

| 서버가 보낸 것 | 뜻 | 학생이 본 것 |
| --- | --- | --- |
| `502` 「AI 응답을 처리하지 못했습니다. 다시 시도해 주세요」 | **다시 눌러 보면 될 일** | 개념 설명을 받지 못했습니다 |
| `503` 「AI 기능을 일시적으로 이용할 수 없습니다」 | **기다려야 하는 일** | 개념 설명을 받지 못했습니다 |

🔴 **이 둘을 나누려고 백엔드가 하는 일이 꽤 많다.** 챗봇 서버가 실패를 네 종류로 나누고,
메인 서버가 그것을 429·502·503 으로 **보존한다** — 그러려고 「모든 예외를 500 으로
바꾸는 그물」보다 **앞에서** 분류한다. 그 노력이 **마지막 한 칸에서 사라지고 있었다.**

⚠️ `400` 도 문제였다. 화면이 지어낸 문구가 서버 것보다 **덜** 완전했다.

```
서버  「학년을 먼저 설정해 주세요. 마이페이지에서 «학년을» 고를 수 있어요」
화면  「학년을 먼저 설정해 주세요. 마이페이지에서 고를 수 있어요」
```

🎯 **같은 말을 두 곳에 적어 두면 한쪽만 다듬게 되고, 학생이 보는 것은 안 다듬은 쪽이다.**

### 무엇을 바꿨나

문구를 **지어내지 않고 서버가 보내 주는 것을 그대로** 보여 준다.

🎯 **한 곳만 예외로 남겼다** — 「이 단원에는 아직 풀 수 있는 문제가 없습니다」.
서버는 「해당 조건에 맞는 문제가 없습니다」라고만 하는데, **화면은 어느 단원인지를
알고 있다.** 화면이 «더 잘» 말할 수 있는 자리는 화면이 말한다.

그리고 어제 만든 「실패를 읽는 자리」를 **다섯 곳이 모두** 쓰게 됐다. 인라인으로 흩어져
있던 에러 모양 선언은 이제 없다.

⚠️ 세션 확인과 인터셉터에서도 같은 것을 고쳤다 — **응답이 «아예 없는» 것(네트워크 끊김)과
서버가 401 을 «준» 것은 다른 일이다.** 앞에서 재발급을 시도하면 헛수고다.

### 검사 3건

```
🔴 502 와 503 이 «다른 말» 로 보이는가
🔴 둘 다 준비된 문구로 «떨어지지» 않는가
🎯 서버가 «더 완전한» 문구를 주면 그것을 쓰는가
```

두 번째가 핵심이다 — 서버 문구를 무시하고 화면 문구를 쓰면 **둘 다 같은 fallback 이 되어
첫 번째 검사도 함께 깨진다.**

---

## §6 🔴 화면이 실패를 「없음」으로 접고 있었다

§5 를 하면서 **손대지 않은 화면들도 훑었다.** 남은 자리들은 에러를 **아예 받지 않는**
`catch {}` 였고, 그중 둘이 이 저장소의 HARD 규칙에 정면으로 걸렸다.

### ① 홈 화면 — 실패가 «빈 목록» 이 됐다

```js
.catch(() => setChapters([]))
```

단원 목록을 못 불러오면 빈 배열이 됐고, 화면은 이렇게 말했다.

> 챕터 정보가 없습니다.

🔴 **그 학년에 «정말로» 단원이 없는 것과, 요청이 «실패한» 것이 학생에게 똑같이 보였다.**
기다리면 되는지, 다시 눌러야 하는지, 원래 없는 건지 알 방법이 없다.

⚠️ **어제 백엔드를 고치면서 이 경로가 새 상태를 내기 시작했다** — 학년 없이 비로그인이면
`401`, 어휘 밖 학년이면 `400`. 둘 다 여기서 「챕터 정보가 없습니다」로 조용히 사라졌을
것이다. 🎯 **한쪽을 고치면 다른 쪽이 그것을 삼키고 있지 않은지 봐야 한다.**

고친 방식: 두 상태를 **따로 들고**, 「못 불러왔다」를 「없다」보다 **먼저** 말한다.
⚠️ 비로그인은 «실패가 아니다» — 그 자리는 오류 문구를 띄우지 않는다.

### ② 진단 테스트 — 「완료 저장 실패」를 아무 말 없이 삼켰다

```js
await completeAssessment();
updateUser({ assessmentCompleted: true });
} catch {
  // 완료 처리 실패해도 결과 화면은 표시
}
```

🎯 **결과 화면을 보여 주는 판단 자체는 옳다** — 20문제를 푼 학생에게서 결과를 뺏으면
안 된다. 문제는 **아무 말도 안 한다**는 것이다.

```
저장이 실패한다 → 서버에는 「진단 완료」가 안 남는다
                → 다음에 로그인하면 20문제를 «처음부터 다시» 받는다
                → 🔴 학생은 왜 또 푸는지 모른다
```

고친 방식: 결과는 그대로 보여 주고, 그 위에 **저장이 안 됐다**를 적는다.

### 🔴 ③ 그리고 내가 세지 않고 적었다

②를 커밋하면서 「이제 에러를 안 받는 `catch {}` 는 한 곳만 남는다」고 적었는데,
**세어 보니 여섯 곳**이었다. 맞춤 문제 화면을 「이미 고쳤다」고 생각하고 다시 안 봤는데,
§5 에서 고친 것은 그 파일의 **두 자리뿐**이었다.

🎯 **「그 파일은 봤다」와 「그 파일을 다 봤다」는 다른 말이다.**

다시 세어 넷으로 줄였고, **남은 넷은 삼키는 것이 맞는 자리**다 — 넷 다 «다음 수단이
있는» 실패이고, 그 사실이 주석에 적혀 있거나 코드로 보인다.

| 남은 자리 | 왜 삼켜도 되나 |
| --- | --- |
| 재발급 실패 | 로그아웃 처리로 **넘어간다**. 문구를 보여 줄 화면이 없다 |
| 수식 렌더 실패 | 원본 글자를 보여 준다. 🎯 못 그리는 것과 **아무것도 안 보이는** 것은 다르다 |
| 보기 JSON 파싱 (2곳) | 다음 방법으로 넘어간다. 「지어내지 않는다」 |

## §7 🔄 「주석으로만 막아 뒀다」를 닫았다 — 그리고 또 하나 나왔다

§6 을 커밋하면서 이렇게 적었다.

> 🔴 두 결함이 다시 생겨도 **검사가 잡아 주지 않는다** — 주석으로만 막아 뒀다.

그 자리를 닫았다. 바꾼 것이 컴포넌트 상태와 렌더 분기라 순수 함수 검사로는 닿지 않아,
**컴포넌트 검사 도구**(화면을 실제로 그려 보고 「무엇이 보이나」를 확인하는 도구)를 들였다.

⚠️ **그래도 순수 로직은 여전히 순수 함수로 뺀다.** 컴포넌트 검사는 느리고(1건에 1초쯤)
깨지기 쉬우므로 **「화면이 무엇을 보여 주는가」가 판단의 핵심일 때만** 쓴다.

### 검사 12건 (43 → 55)

| 어디 | 몇 건 | 무엇을 못 박나 |
| --- | ---: | --- |
| 홈 | 6 | 「못 불러왔다」와 「없다」를 **다르게** 말하는가. 비로그인은 **실패가 아니다** |
| 진단 | 5 | 저장이 실패해도 결과는 보여 주되 **말은 하는가**. 그때 로그인 상태도 완료로 **안 바꾸는가** |
| 수식 파서 | 1 | 아래 참고 |

### 🔴 검사를 쓰다가 결함 하나가 더 나왔다

진단 결과 화면이 **통째로** 터졌다. 따라가 보니 수식 파서가 **값 없음에서 죽고** 있었다.

```
parseSegments(undefined) → text.length 를 읽는다 → 터진다 → 화면 «전체» 가 사라진다
```

이번에는 내 검사 픽스처가 필드 이름을 틀려서 났지만(`correctAnswer` 를 `answer` 로),
🔴 **서버가 그 필드를 `null` 로 보내거나 빼면 실제로 같은 일이 난다.** 타입은 문자열로
적혀 있지만 런타임에는 그대로 들어온다.

🎯 **못 그리는 것과 «아무것도 안 보이는» 것은 다르다** — 이 파일은 이미 수식 렌더
실패를 그렇게 다루고 있었다(원본 글자를 보여 준다). 같은 판단을 맨 앞에도 뒀다.

⚠️ **픽스처도 고쳤다.** 검사 픽스처가 서버 응답과 **모양이 다르면 실제와 다른 것을
재게 된다** — 이번이 그 예다. 🎯 픽스처는 「대충 맞는 것」이 아니라 「서버가 실제로
보내는 것」이어야 한다.

### 함께 — 챕터 카드의 가드를 하나 넓혔다

```
stats !== null  →  stats != null
```

서버는 지금 통계가 없을 때 `myStats` 를 **`null` 로** 보낸다(필드를 빼지 않는다).
그런데 누가 응답에서 `null` 필드를 빼는 설정을 켜면 값이 **없는 것**이 되어 화면이
터진다. 둘 다 「통계 없음」이므로 같이 받는다.

## 🔴 확인 못 한 것

- 🔄 **§1~§3 은 코드를 안 바꿨지만 §4·§5 는 바꿨다.** 어휘 모듈이 새로 생겼고 두 서비스가
  그것을 쓴다. ⚠️ **실제로 모르는 학년을 보내 본 것은 아니다** — 검사는 함수를 직접
  불러서 확인했고, Spring 이 그런 값을 보내는 상황은 재현하지 않았다
  (Spring 은 enum 에서 꺼낸 값만 보내므로 그 상황은 «두 서버의 어휘가 어긋났을 때» 뿐이다)
- 🔄 **이 항목은 §3 에서 닫았다.** 노트가 인용한 «이름» 을 전부 코드와 대조해 하나를
  더 찾았다. ⚠️ 다만 대조한 것은 **이름**이지 **설명의 내용**이 아니다 — 「왜 이렇게 했나」가
  지금도 맞는지는 사람이 읽어야 안다
- **브라우저로 화면을 보지 않았다.** §5 는 «어떤 문구가 나가는지» 를 코드와 검사로
  확인한 것이지 502·503 을 실제로 받아 본 것이 아니다. 화면 저장소에는 컴포넌트 검사가
  없어서, 새 검사 3건도 «문구를 고르는 함수» 를 잴 뿐 화면에 그려지는 것은 못 잰다
- 어제 커밋 메시지에 남은 틀린 숫자는 **고칠 수 없다.** 이미 머지됐고, 이력을 다시 쓰지
  않는 것이 규율이다
