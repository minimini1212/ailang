## §3 작업 하나 — 인증 메일을 무한히 보낼 수 있었다

**무엇이 문제였나 (역할 → 작용 → 결과)**

```
메일 보내기 요청은 로그인 없이 누구나 부를 수 있다
  → 한 사람이 몇 번 불렀는지 아무도 세지 않는다
  → 임의의 주소로 메일을 «무한히» 보낼 수 있다
     · 남의 메일함을 우리 서비스 이름으로 채울 수 있다
     · 메일 발송 계정의 하루 한도가 소진되면 «진짜 가입자» 가 코드를 못 받는다
```

```
인증 코드는 6자리 숫자다 (경우의 수 100만)
  → 몇 번 틀렸는지 세지 않는다
  → 맞을 때까지 넣어 보면 «반드시» 뚫린다. 시간 문제일 뿐이다
```

**어떻게 고쳤나**

요청이 올 때마다 저장소에 횟수를 하나씩 올리고, 정해 둔 수를 넘으면 거절한다. 여기서
**순서가 규칙**이다.

| 무엇 | 어디에 둬야 하나 | 뒤에 두면 |
| --- | --- | --- |
| 발송 횟수 확인 | 메일을 보내기 **전** | 거절된 요청도 메일을 한 통씩 보낸다 — 막은 의미가 없다 |
| 발송 횟수 확인 | 가입 여부를 묻기 **전** | 「이미 가입된 메일입니다」 응답으로 **가입자 명단을 무제한 조회**할 수 있다 |
| 입력 횟수 세기 | 코드를 대조하기 **전** | 틀린 입력이 안 세어진다 — 제한이 없는 것과 같다 |

그리고 입력 횟수를 넘기면 **코드 자체를 버린다.** 안 버리면 횟수 세기가 만료될 때까지
기다렸다가 같은 코드로 이어서 넣으면 되므로, 센 의미가 사라진다.

🔴 **「틀렸다」와 「너무 많이 틀렸다」를 다른 응답으로 구분했다.** 앞은 다시 넣어 보면 되고,
뒤는 코드가 이미 사라졌으니 **다시 받아야** 한다. 같은 문구로 뭉개면 학생이 같은 코드를
계속 넣으며 왜 안 되는지 모른다.

⚠️ **「몇 번까지 허용할 것인가」는 정하지 않았다.** 그것은 운영자가 정할 일이다. 대신
코드에 숫자를 박지 않고 설정으로 뺐다 — 정해지면 **설정 세 줄만 바꾸면 되고 재배포가
필요 없다.** 정해지기 전까지는 잠정값(창 1시간에 5통 · 코드 하나에 5회)으로 돈다.

## §4 작업 둘 — 데이터베이스와 챗봇 서버가 이 PC 밖에서도 보였다

**무엇이 문제였나 (역할 → 작용 → 결과)**

```
컨테이너 설정이 포트를 «모든 인터페이스» 에 열고 있었다
  → 같은 와이파이(카페·학교·공유기)에 붙은 아무나 곧바로 닿는다
  → 저장소에는 «리프레시 토큰 원문» 과 «로그아웃 기록» 이 들어 있다
     · 남의 토큰을 읽어 그 계정으로 로그인할 수 있다
     · 로그아웃 기록을 지워 로그아웃을 되돌릴 수 있다
     · 「인증 완료」 표시를 직접 넣어 메일 인증을 건너뛸 수 있다
  → 게다가 저장소에 «비밀번호가 없었다». 닿기만 하면 끝이다
```

**어떻게 고쳤나**

세 컨테이너(데이터베이스 · 저장소 · 챗봇 서버) 전부 **이 PC 에서만 닿도록** 묶었다.
그리고 저장소에 비밀번호를 걸 수 있게 배선했다 — 설정값을 넣으면 두 서버가 같은 값으로
붙는다.

⚠️ **비밀번호는 아직 실제로 안 걸려 있다.** 값을 넣는 것은 사용자의 일이다(Claude 는
비밀 값이 든 파일을 쓰지 않는다). 값이 비어 있으면 저장소는 예전처럼 인증 없이 뜬다.
**이것을 「괜찮다」로 바꾸지 않고 그대로 적어 둔다** — 안 적으면 다음 사람이 「닫혔다」로
읽는다.

🔬 **포트를 아예 안 여는 것이 더 안전하지만 지금은 못 한다.** 메인 서버가 컨테이너 밖
(이 PC 자체)에서 뜨기 때문에, 이 PC 에서 닿을 수 있어야 한다. 메인 서버도 컨테이너로
넣을지는 **배포 방식이 정해져야** 답이 나온다.

## §5 🔴 작업 셋 — 나흘 전에 「고쳤다」고 적어 둔 것이 안 고쳐져 있었다

**이것이 오늘 가장 중요한 발견이다.**

### 배경: 나흘 전에 무엇을 고쳤다고 했나

같은 학생이 답을 **거의 동시에 두 번** 내면(버튼이 두 번 눌리면 일어난다) 세 가지가 깨진다.

| 무엇이 겹치나 | 학생에게 보이는 것 |
| --- | --- |
| 통계 기록을 둘 다 새로 만들려 한다 | **답을 냈는데 오류 화면** |
| 둘 다 같은 값을 읽고 각각 1씩 더한다 | 한 건이 **사라진다** — 정답률이 어긋난다 |
| 같은 문제를 둘 다 「처음 푼 것」으로 센다 | 한 문제가 정답률에 **두 번** 들어간다 |

2026-09-11 에 이것을 고쳤다고 기록했고, 코드에는 *「여기서 죽지 않는다. 학생은 오류 화면을
안 본다」* 라는 주석까지 달려 있었다. 다만 그때는 **확인할 수단이 없어서** 「고쳤지만 확인
못 함」으로 남아 있었다.

### 오늘: 실제로 재 봤더니 여전히 오류가 났다

데이터베이스를 쓰는 검사를 새로 만들어 두 요청을 진짜로 겹쳐서 보냈다. **둘 다 실패했다.**

**무엇이 문제였나 (역할 → 작용 → 결과)**

```
데이터 저장에 실패하면 → 그 덩어리 전체가 «되돌릴 수밖에 없는» 상태로 표시된다
실패를 그 덩어리 «안» 에서 삼켰다
  → 예외는 사라진다. 여기까지는 의도대로다
  → 그런데 함수가 정상적으로 끝나므로 «저장을 시도한다»
  → 이미 되돌리기로 표시돼 있으니 «거기서 다시» 오류가 난다
  → 오류의 «이름만» 바뀌고, 학생이 보는 것은 똑같은 오류 화면
```

즉 **고친 것이 아니라 증상의 이름만 바뀌어 있었다.** 나흘 동안 그 상태였다.

**어떻게 고쳤나**

> 🎯 **실패를 「없던 일」로 만들려면, 그 실패로 더럽혀진 덩어리가 이미 끝난 «뒤» 에
> 잡아야 한다.** 안쪽은 그냥 던지고, 바깥이 잡는다.

안쪽 함수는 이제 아무것도 삼키지 않는다. 실패는 그대로 던지고 그 덩어리는 깨끗이
되돌려진다. 바깥은 그 실패를 받아 「남이 먼저 만들었구나」로 읽고 그 기록을 쓴다.
고친 뒤 같은 검사가 **둘 다 통과**했다.

🔴 **이 규칙을 규율 문서에 새 항목으로 올렸다** — 「일단 넣어 보고 실패하면 남이 먼저
한 것」이라는 패턴 전부에 해당하기 때문이다. 지금은 한 군데뿐이지만, 같은 모양이 또
나오면 같은 함정이 기다린다.

## §6 🔴 헛일을 했다 — 같은 작업이 이미 다른 가지에 있었다

설정 세 가지(화면 주소를 설정값 하나로 · 질의문 로그 끄기 · 이미지의 개발용 재시작 옵션
제거)를 오늘 고쳤는데, **똑같은 작업이 이미 다른 가지에 올라가 있었고** 오늘 본문에
합쳐졌다. 그쪽이 더 완전하기까지 했다 — 데이터베이스 **접속 주소**까지 설정으로 빼 놨고,
설정을 읽는 구조도 더 낫다.

**무엇이 문제였나 (역할 → 작용 → 결과)**

```
일을 시작할 때 «원격 저장소를 받아 오지» 않았다
  → 내 컴퓨터의 본문 가지가 나흘 낡은 상태였다
  → 이미 끝난 일을 「아직 안 된 일」로 읽고 다시 했다
  → 합칠 때 같은 파일 7개가 충돌했다
```

그리고 더 나쁜 것: 시작할 때 가지 목록에 **「설정을 밖으로 뺀다」는 이름의 가지가 보였는데
열어 보지 않았다.** 이름이 이미 답을 말해 주고 있었다.

🎯 **다음부터는 일을 시작하기 전에 원격을 받아 오고, 끝나지 않은 가지의 «내용» 을 본다.**
이름만 보고 넘기지 않는다.

**어떻게 정리했나** — 겹친 자리는 전부 **본문 쪽(이미 합쳐진 것)을 택했다.** 내가 붙인
설정 이름 하나가 본문과 달랐는데(`APP_BACKEND_ORIGIN` ↔ `APP_OAUTH2_CALLBACK_BASE`),
본문 쪽으로 맞췄다. 오늘 작업 중 **겹치지 않은 것만 남았다** — 인증 상한, 포트 닫기,
저장소 비밀번호, 그리고 §5 의 결함 수정과 검사들.

⚠️ 이 헛일의 크기: 설정 세 가지, 약 반 시간. **결과물은 한 줄도 안 남았다.**

## §7 재 본 것 — 데이터베이스 실측

데이터베이스가 떠 있어서, 목록에 「확인 필요」로 남아 있던 항목들을 직접 셌다.

| 목록의 주장 | 실측 결과 |
| --- | --- |
| 「문제가 하나도 없는 챕터 2개」 | ❌ **없다.** 8개 챕터 전부 문제가 있고, 가장 적은 곳도 75문제다 |
| 「정체 불명의 표 5개 — 지우기 전에 확인」 | ✅ **정체가 밝혀졌다. 지우면 안 된다.** 데이터 도구가 여러 건을 한꺼번에 지우거나 고칠 때 쓰는 **임시 작업대**다. 항상 비어 있는 것이 정상이고, 우리 표 5개와 하나씩 짝을 이룬다 |
| 「(챕터 × 난이도) 24칸 중 10칸이 비어 있다」 | ✅ **맞다. 10칸이다** |

### 🔴 난이도 쏠림이 눈으로 보인다

| 챕터 | 하 | 중 | 상 | 합 |
| --- | ---: | ---: | ---: | ---: |
| 소인수분해 | 73 | 1 | 1 | 75 |
| 정수와 유리수 | **165** | 0 | 0 | 165 |
| 문자와 식 | 177 | 64 | 0 | 241 |
| 좌표평면과 그래프 | 0 | **104** | 0 | 104 |
| 기본 도형 | 0 | **184** | 0 | 184 |
| 평면도형 | 0 | 70 | 47 | 117 |
| 입체도형 | 0 | 0 | **168** | 168 |
| 통계 | 39 | 11 | 28 | 78 |

「정수와 유리수」는 **165문제 전부가 하**이고 「입체도형」은 **168문제 전부가 상**이다.
학생이 잘해서 난이도가 올라가도 그 단원에는 올라갈 자리가 없다. 지금은 이웃 난이도로
대신 주어 **고장은 막았지만**, 근본은 「난이도를 무엇으로 정할 것인가」라는 결정이다.

### 🔴 새로 찾은 것 — 객관식 500문제 중 14문제는 «맞힐 수 없다»

정답 칸을 모양별로 세다가 찾았다.

```
객관식 500문제의 정답 칸 모양
  ① 보기 번호 한 글자 (①②③④⑤)      429문제   ← 정상
  ② 12자 이하의 그 밖의 것              57문제
  ③ 12자를 넘는 «풀이 전문»             14문제   ← 🔴 정답이 아니다
```

③은 정답 칸에 *「① 어떤 수를 a 라고 하면 … 따라서 a = 1/6」* 같은 **풀이 과정 전체**가
들어가 있다. 채점은 「학생이 고른 번호」와 「정답 칸」을 맞춰 보는데, 정답 칸이 저러면
**학생이 무엇을 골라도 틀린 답이 된다.**

⚠️ **오늘은 안 고쳤다.** 고치려면 「풀이 부분을 버릴 것인가, 해설 칸으로 옮길 것인가」를
정해야 하고, 그건 **사람이 정할 일**이다. 목록에 올려 두었다.

## §8 검증 — 무엇을 어디까지 확인했나

```
검사 73건 전부 통과 (실패 0 · 오류 0 · 건너뜀 0)
  시작 시점 59건 → 오늘 14건 추가
```

| 새 검사 | 몇 건 | 무엇이 필요한가 |
| --- | ---: | --- |
| 허용 횟수 판정의 경계 | 4 | 없음 (순수 로직) |
| 인증 메일·코드의 «순서» | 7 | 없음 (저장소와 메일 서버를 가짜로 대체) |
| 동시 제출 | 2 | 🔴 **실제 데이터베이스** |
| 같은 원본 문제의 중복 저장 차단 | 1 | 🔴 **실제 데이터베이스** |

### 🔴 새 검사가 옛 코드에서 빨간불인지 실제로 확인했다

「양쪽 다 통과하는 검사는 아무것도 못 박은 게 없다」는 규율에 따라, **일부러 코드를
망가뜨려 보고** 검사가 잡는지 봤다.

| 넣어 본 변형 | 결과 |
| --- | --- |
| 허용 횟수 비교를 한 칸 옮김 (5회 허용이 조용히 4회가 된다) | ✅ 2건 빨간불 |
| 발송 횟수 확인을 메일 발송 **뒤**로 옮김 | ✅ 2건 빨간불 |
| 입력 횟수 세기를 코드 대조 **뒤**로 옮김 | ✅ 1건 빨간불 |
| (동시 제출 검사는 **고치기 전 코드에서 실제로 2건 다 빨간불**이었다 — §5) | ✅ |

확인 뒤 전부 원래대로 되돌렸고, 다시 73건 전부 통과하는 것을 봤다.

### ⚠️ 못 한 것

| 무엇 | 왜 |
| --- | --- |
| **적재를 두 번 돌려 보기** | 지금 적재는 「기출문제가 한 건이라도 있으면 통째로 건너뛴다」라서, 이미 1,132건이 들어 있는 이 데이터베이스에서는 **두 번째 실행이 아무 일도 안 한다.** 진짜로 재려면 적재 방식을 「문제 하나하나를 원본 번호로 확인」하도록 바꿔야 하는데, 그러면 **앞으로 서버를 켤 때마다 2,300개 파일을 다시 읽게 된다.** 이건 비용을 맞바꾸는 «설계 결정»이라 오늘 범위 밖으로 뒀다 |
| 저장소 비밀번호가 실제로 걸리는지 | 비밀 값 파일은 사용자가 채운다 |
| 챗봇 서버 쪽 검사 | 파이썬 쪽에는 검사가 **0건**이다. 오늘 만들지 않았다 |

## §9 한눈에 보기

### ✅ 닫은 것

| 무엇 | 결과 |
| --- | --- |
| 🔴 나흘 전 「고쳤다」가 실제로는 안 고쳐져 있었다 | 실패를 삼키는 자리를 옮겼다. 규율 문서에 새 항목으로 올렸다 |
| 🔴 인증 메일을 무한히 보낼 수 있었다 | 창 하나당 상한. 값은 설정으로 |
| 🔴 인증 코드를 무한히 넣어 볼 수 있었다 | 입력 상한 + 넘으면 코드 폐기 |
| 🔴 데이터베이스·저장소·챗봇 서버가 같은 망에 열려 있었다 | 이 PC 에서만 닿게 묶었다 |
| 🔴 저장소에 비밀번호를 걸 수 없었다 | 배선했다 (⚠️ 값은 사용자가 넣어야 실제로 걸린다) |
| 검사를 한 번도 안 돌려 봤다 | 73건 전부 통과 확인 |
| ⚠️ 설정 세 가지(화면 주소·질의문 로그·재시작 옵션) | **헛일이었다** — 이미 다른 가지에 있었고 오늘 본문에 합쳐졌다. 본문 쪽을 택했다 (§6) |
| 남은 일 목록에 **이미 끝난 항목 4개**가 열려 있었다 | 접었다 |
| 🔴 **규율 문서가 이미 고쳐진 결함 12개를 «현재도 그렇다»고 적고 있었다** | 전부 코드로 확인하고 「예전에 그랬다」로 고쳤다. 규칙 자체는 그대로 뒀다 — 규칙이 왜 생겼는지가 그 안에 있다 |

### 🔴 새로 알게 된 것 (전부 목록으로 넘겼다)

- 객관식 **500문제 중 14문제**는 정답 칸에 풀이가 들어가 있어 **맞힐 수 없다**
- 🔴 **일을 시작할 때 원격을 안 받아 와서 설정 작업을 두 번 했다** (§6)
- 「문제가 없는 챕터 2개」는 **이미 없다**
- 「정체 불명의 표 5개」는 **데이터 도구의 임시 작업대** — 지우면 안 된다
- 적재를 두 번 돌리는 검사는 **적재 방식을 바꿔야** 가능하고, 그건 설계 결정이다
