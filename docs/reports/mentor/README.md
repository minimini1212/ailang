# docs/reports/mentor — 멘토님 보고서용

**성격:** 멘토(외부)에게 보고하는 정리본. 일일 리포트보다 **압축·맥락 위주**, 결정과 근거 중심.

- 일일 리포트([`../daily/`](../daily/))가 「매일의 작업 로그」라면, 여기는 **보고 시점 기준의
  정리·요약본**이다.
- 파일명: `MENTOR_<YYYY-MM-DD>_<주제>.md`
  (예: `MENTOR_2026-08-27_grading-integrity.md`).
- 담을 것: 지난 기간 요약, 핵심 의사결정과 근거, 막힌 지점·질문, 다음 계획.
- 원자료(측정치·조사 상세)는 [`../../research/`](../../research/) 나
  [`../daily/`](../daily/) 를 **링크로 참조** — 여기서 중복 생산 금지.

## 🔴 읽는 사람은 이 코드를 모른다

멘토는 이 레포를 매일 보지 않는다. 그래서 일일 리포트보다 **더 엄격하게** 규율을 지킨다.

- **§0 용어표는 선택이 아니다.** 「기출/AI 생성」·「정답률」·「난이도 조정」이 무슨 뜻인지
  모르는 채로 숫자를 읽게 하면 안 된다.
- **「무엇이 문제인가」를 코드가 아니라 결과로 설명한다.**
  ✅ *"학생이 스스로 채점한 결과를 서버가 그대로 저장한다 → 정답률을 조작할 수 있다
  → 그 정답률로 다음 문제 난이도가 정해지므로 「맞춤형」이 성립하지 않는다"*
  ❌ *"`submitAnswer` 의 `selfJudge` 처리"*
- **비율은 분모와 함께.**

## 🔴 결정을 요청하는 자리를 분리해 둔다

이 프로젝트에는 **혼자 정하면 안 되는 항목**이 모여 있다
([`../../PRD.md`](../../PRD.md) §7). 보고서에 「검토 부탁드립니다」로 흘리지 말고
**무엇을·왜 지금·선택지와 각각의 대가**를 표로 세워 묻는다.

📌 **결정이 나오면 그 결정을 받아 적는 곳은 여기가 아니다.**
[`../../rules/`](../../rules/) 의 해당 문서로 승격하고, 이 보고서는 그날의 기록으로 남긴다.
