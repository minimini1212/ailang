# 챕터를 무엇으로 묶을 것인가 — 2026-09-09

> **본 날짜: 2026-09-09**
> **무엇을 했나**: 「챕터가 331개라 난이도가 영원히 안 움직인다」를 어떻게 풀지,
> 원본 자료에 어떤 묶음 단위가 실제로 있는지 전수로 찾았다.
> **어떻게**: 원본 JSON 1,152건의 `question_info` 13개 필드를 전부 파싱해
> 후보별 챕터 수·챕터당 문제 수·(챕터×난이도) 분포를 계산했다. DB 쓰기 없음.
>
> 🔴 이 문서는 **재료**다. 대응은 [`../DATA_CONTRACT.md`](../DATA_CONTRACT.md) §2·§5 와
> [`../../TODOS.md`](../../TODOS.md) 로 간다.

## §0. 이 문서를 처음 보는 사람에게

| 말 | 뜻 |
| --- | --- |
| **챕터** | 학생이 고르는 학습 단위. 「소인수분해」처럼 목록에 뜨는 그것. |
| **유형** | 「맞꼭지각(1)」처럼 문제를 잘게 나눈 이름. 원본의 `question_topic_name`. |
| **난이도 고리** | 학생 정답률 → 난이도 조정 → 다음 문제 난이도. 이 순환이 이 앱의 핵심이다. |
| **3문제 문턱** | 난이도 조정은 **한 챕터에서 3문제 이상** 풀어야 시작한다(`UserChapterStats`). |
| **(챕터×난이도) 칸** | 맞춤 문제가 실제로 조회하는 단위. 챕터 8개 × 난이도 3종 = 24칸. |

## §1. 왜 찾았나

실측(2026-08-31)에서 이렇게 나왔다.

```
챕터 수              331개      ← question_topic_name 을 그대로 챕터로 썼다
챕터당 평균          3.5문제
문제 3개 이하 챕터   200개 (60%)
```

난이도 조정은 **3문제 문턱**이 있으므로, 챕터의 60% 는 **난이도가 영원히 안 움직인다.**
실사용 통계 40건 중 3문제 이상 푼 챕터가 **1개**뿐인 것이 그 증거다.

즉 이 앱의 핵심인 난이도 고리가 **자료 구조 때문에** 안 돈다.

## §2. 원본에 어떤 층이 있나 — 3층뿐이다

`question_topic` 코드가 **7자리**인데, 자릿수마다 뜻이 있다.

```
7 1 03 001
│ │ │  └── 유형 일련번호
│ │ └───── 단원 (question_unit 과 같다)
│ └─────── 학기
└───────── 학년 (7 = 중1)
```

🎯 **`question_unit` 은 (학년·학기·영역·topic코드 앞4자리)와 1:1 이다** — 전수 확인.

```
unit 01 = M1 1학기 · 수와 연산      코드 7101    unit 05 = M1 2학기 · 도형과 측정    코드 7205
unit 02 = M1 1학기 · 수와 연산      코드 7102    unit 06 = M1 2학기 · 도형과 측정    코드 7206
unit 03 = M1 1학기 · 변화와 관계    코드 7103    unit 07 = M1 2학기 · 도형과 측정    코드 7207
unit 04 = M1 1학기 · 변화와 관계    코드 7104    unit 08 = M1 2학기 · 자료와 가능성  코드 7208
```

🔴 **중단원 층은 «존재하지 않는다».** 학기 → 단원 → 유형 3층이 전부다.

### 중간 크기를 만들어 보려 했지만 안 된다

| 후보 | 챕터 수 | 챕터당 평균 | 문제 3개 이하 |
| --- | --- | --- | --- |
| 현재: `question_topic_name` | 331 | 3.5 | **200개 (60%)** |
| 유형명에서 「(3)」·「-보조선 2개」를 떼어 묶기 | 297 | 3.9 | **175개 (59%)** ❌ 거의 그대로 |
| topic 코드 앞 3자리 (학년+학기) | 2 | 576 | 0 |
| **`question_unit` (대단원)** | **8** | **144** | **0개** ✅ |

즉 선택지는 **8개 아니면 331개**다. 자료가 그렇게 강제한다.

## §3. 대단원 8개로 묶으면 이렇게 된다

이름은 원본에 없어서 사람이 채웠다
([`../../src/main/resources/data/chapter-titles.csv`](../../src/main/resources/data/chapter-titles.csv)).
각 단원의 실제 유형 목록으로 확인한 이름이다.

| --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | 소인수분해 | 1학기 · 수와 연산 | 76 | 74 | 1 | 1 | 28 |
| 2 | 정수와 유리수 | 1학기 · 수와 연산 | 167 | 167 | 0 | 0 | 32 |
| 3 | 문자와 식 | 1학기 · 변화와 관계 | 246 | 182 | 64 | 0 | 71 |
| 4 | 좌표평면과 그래프 | 1학기 · 변화와 관계 | 106 | 2 | 104 | 0 | 26 |
| 5 | 기본 도형 | 2학기 · 도형과 측정 | 185 | 1 | 184 | 0 | 51 |

## §4. 🔴 그런데 여기서 «새 사실» 이 하나 드러났다

위 표를 세로로 보면 보인다. **난이도 축이 단원 축과 거의 같은 축이다.**

```
입체도형        하   0 · 중   0 · 상 168     ← 전부 상
정수와 유리수    하 167 · 중   0 · 상   0     ← 전부 하
```

(챕터 8 × 난이도 3) **24칸 중 7칸이 비어 있다.**

| 빈 칸 | | 3문제 미만인 칸 | |
| --- | --- | --- | --- |
| 정수와 유리수 → 중 | 0 | 소인수분해 → 중 | 1 |
| 정수와 유리수 → 상 | 0 | 소인수분해 → 상 | 1 |
| 문자와 식 → 상 | 0 | 좌표평면과 그래프 → 하 | 2 |
| 좌표평면과 그래프 → 상 | 0 | 기본 도형 → 하 | 1 |
| 기본 도형 → 상 | 0 | | |
| 입체도형 → 하 | 0 | | |
| 입체도형 → 중 | 0 | | |

🎯 이것은 [`difficulty-origin-2026-09-07.md`](difficulty-origin-2026-09-07.md) 의 결론과
**같은 사실의 다른 얼굴**이다. 그때 `question_unit` 의 설명력이 86.4% 로 가장 높았던 이유가
이것이다 — **난이도를 손으로 정한 사람이 사실상 단원별로 정했다.**

### 이게 왜 «고장» 인가

맞춤 문제는 「챕터 + 학생의 현재 난이도」로 문제를 찾는다. 통계가 없는 학생의 초기 난이도는
**중(MEDIUM)** 이다. 그래서 학생이 **「입체도형」을 처음 열면 중 0건** 이고,
예전 코드는 거기서 `orElseThrow` → **404** 였다.

⚠️ **이 결함은 대단원으로 묶어서 «생긴» 것이 아니다.** 331챕터에서는 챕터당 평균 3.5문제라
훨씬 자주 났다. 다만 챕터가 331개일 때는 아무도 셀 수 없었을 뿐이다.

### 대응 — 폴백을 넣었다

`DifficultyFallback` 이 「요청 난이도 → 한 단계 아래 → 나머지」 순서를 준다.
쉬운 쪽을 먼저 보는 이유는, 못 풀면 학생이 그만두기 때문이다.
🔴 **난이도를 «바꿔치기» 하지 않는다** — 응답에는 실제로 준 문제의 난이도가 실린다.

## §5. 유형 331종은 버리지 않았다

챕터가 넓어진 만큼 `PROBLEMS.TOPIC` 에 유형명을 남긴다. 두 가지 이유다.

1. **개념 설명이 뭉뚱그려진다.** 예전에는 Gemini 에 「맞꼭지각(1)」이 갔는데
   챕터명만 보내면 「기본 도형」이 간다. 그래서 `단원 · 유형` 을 함께 보낸다.
2. **나중에 2단 구조로 갈 길을 남긴다.** 대단원 8개가 너무 넓다고 판단되면
   유형을 소단원으로 승격할 수 있다 — 자료를 버리지 않았으므로 다시 적재할 필요가 없다.

같이 넣은 것이 하나 더 있다: **`PROBLEMS.SOURCE_ID`(원본 AI Hub id).**
이게 없어서 적재가 「전부 아니면 전무」였다 — 절반만 들어간 상태에서 나머지를 채우거나
새 학년 자료를 덧붙일 수 없었다. 표를 비우고 다시 채우는 지금이 **넣을 수 있는 유일한 때**다.
