## §0. 이 문서를 처음 보는 사람에게

| 말 | 뜻 |
| --- | --- |
| **적재(DataLoader)** | 앱이 처음 뜰 때 JSON 파일들을 읽어 DB 문제 표를 채우는 작업. |
| **OCR** | 종이 문제를 스캔해 글자로 바꾼 것. 원본이 이미지라 텍스트가 깨끗하지 않을 수 있다. |
| **bbox** | 이미지 안에서 「이 글자가 여기 있다」를 표시한 네모 상자. 정답이 이 안에 들어 있다. |
| **기출** | 사람이 낸 실제 문제. AI 가 만든 문제와 구분한다. |

## §1. 파일이 두 폴더로 나뉘어 있다

```
problem-dir/          답안-dir/
  <무엇>.json    ←→     <무엇>.json
```

**두 파일을 잇는 것은 파일명이 아니라 JSON 안의 `id` 값이다.**
적재는 양쪽 폴더의 `*.json` 을 전부 읽어 `id` 로 짝을 맞춘다.

🔴 **짝이 없으면 그 문제는 통째로 버려진다.** 답안 파일이 없거나 `answer_info` 가 비면
`skipped` 로 세어지고 끝이다.

## §2. 읽는 필드

### 문제 파일

```
{
  "id": "…",                          ← 답안 파일과 짝을 맞추는 열쇠
  "question_info": [{
    "question_grade":      "M1",      → 학년
    "question_unit":       "3",       → 챕터 표시 순서
    "question_topic_name": "일차방정식", → 유형 이름 (🔄 아래 각주)
    "question_type1":      "선택형",   → 객관식/단답형
    "question_step":       "표준",     → 난이도 (1순위)
    "question_difficulty":  3          → 난이도 (2순위, 1~5 숫자)
  }],
  "OCR_info": [{
    "question_text": "다음 중 …"       → 문제 본문
  }]
}
```

⚠️ **`question_info` 와 `OCR_info` 는 배열인데 적재는 `[0]` 만 쓴다.**
둘 이상 들어 있는 파일이 있는지 확인되지 않았다 (§3).

### 답안 파일

```
{
  "id": "…",
  "answer_info": [{
    "answer_text": "…",               → 해설
    "answer_bbox": [
      { "type": "answer", "text": "②" },   ← 🎯 정답은 여기서 뽑는다
      { "type": "…",      "text": "…" }
    ]
  }]
}
```

**정답 추출**: `answer_bbox` 에서 `type == "answer"` 인 **첫 번째** 항목의 `text`.
비어 있거나 없으면 그 문제는 버려진다.

### 값 변환 규칙

| 원본 | → | 우리 값 |
| --- | --- | --- |
| `E3` `E4` `E5` `E6` | → | `ELEM_3` `ELEM_4` `ELEM_5` `ELEM_6` |
| `M1` `M2` `M3` | → | `MIDDLE_1` `MIDDLE_2` `MIDDLE_3` |
| `H1` | → | `HIGH_1` |
| `기본` / `표준` / `심화` | → | `LOW` / `MEDIUM` / `HIGH` |
| `question_difficulty` ≤2 / ≤3 / 그 외 | → | `LOW` / `MEDIUM` / `HIGH` |
| `선택형` | → | `MULTIPLE_CHOICE` |
| 그 밖의 모든 값 | → | `SHORT_ANSWER` |

🔴 **`question_type1` 은 `선택형`만 알고 나머지는 전부 단답형으로 떨어진다.**
원본에 다른 객관식 표기(`객관식`·`4지선다` 등)가 있으면 조용히 단답형이 된다.
실물로 확인해야 할 항목이다 (§3).

## §3. 확인 못 한 것 — 🔴 실물을 여는 사람이 채울 것

| # | 무엇 | 왜 중요한가 |
| --- | --- | --- |
| 1 | `question_type1` 에 실제로 어떤 값들이 있나 | `선택형` 외의 객관식 표기가 있으면 전부 단답형이 된다 |
| 2 | `question_info` / `OCR_info` 배열이 2개 이상인 파일이 있나 | `[0]` 만 쓰므로 나머지는 버려진다 |
| 3 | `question_unit` 이 항상 숫자 문자열인가 | 🔴 `Integer.parseInt` 라 아니면 예외 → 그 문제가 버려진다 |
| 4 | `answer_bbox` 에 `type == "answer"` 가 **여러 개**인 경우 | 복수정답 문제다. 지금은 **첫 건만** 쓴다 → 오답 처리된다 |
| 5 | 정답 표기의 실제 분포 | `②` 인가 `2` 인가 `(2)` 인가. 채점 정규화가 여기 달려 있다 |
| 6 | 보기(선택지)가 본문에 어떻게 섞여 있나 | 🎯 화면에서 보기를 따로 그릴 수 있는지가 여기 달려 있다 |
| 7 | `id` 가 실제로 유일한가 | 겹치면 뒤에 읽은 파일이 앞을 덮는다 (`LinkedHashMap.put`) |
| 8 | 전체 몇 건이고 학년별로 몇 건인가 | 🔴 **진단 테스트가 학년당 20문제를 요구한다.** 부족하면 조용히 적은 배열이 나간다 |
| 9 | 자료 이용 조건 (벡터 저장소 적재 가능 여부) | Phase 3(RAG) 의 전제다 |

⚠️ **8번은 지금 화면에 드러나는 결함으로 이어져 있다.** `/api/problems/assessment` 는
문제가 부족해도 404 가 아니라 **20개보다 적은 배열**(0개일 수도)을 준다.

## §4. 알려진 후처리 — 정답 표기 정규화

원본 정답이 `"① 어떤 수를 a라고…"` 처럼 **원문자 + 설명 문장**으로 들어 있는 건이 있어,
저장된 데이터를 한 번 정리하는 스크립트가 있다: `scripts/normalize_answers.py`

- `①②③④⑤` 를 순서대로 뽑아 `"1"` 또는 `"1,3"` 로 바꾼다
- 원문자가 없으면 `(1)`~`(5)` 형태를 시도한다
- 둘 다 없으면 건드리지 않는다

⚠️ **1회성 스크립트이고 DB 접속 정보가 하드코딩돼 있다.** 돌리기 전에 파일을 열어 확인할 것.

🎯 **이 스크립트가 존재한다는 사실 자체가 §3-5 의 답을 일부 말해 준다** —
정답 표기가 깨끗하지 않았다는 뜻이다. 얼마나 많은 건이 이 스크립트로도 안 풀렸는지는
기록이 남아 있지 않다.
